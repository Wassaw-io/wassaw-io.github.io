When to stop tuning, and when to ignore the drift alarm

A tutoring center wanted a list of which students to contact before they left. Building it meant three decisions that often go the wrong way: which model to deploy, whether to keep improving it, and when to retrain it. Here each one went against the usual practice, and each saved time or money.

ProblemRank the center’s 570 current students by how much it stands to lose if each one leaves, and keep that ranking trustworthy as the mix of students changes.

What I didCompared gradient boosting with logistic regression on held-out students, computed the best score any model could reach on the data collected, built a command-line tool that validates, scores, and monitors, and tested the drift alarm against a real change in who enrolled.

DecisionDeploy the simpler model, and put the next effort into collecting different data rather than tuning. Do not retrain on drift alone: a drift score of 0.60, more than twice the usual threshold, came with no loss in accuracy.

A standard approach against this analysis

A standard approach

Tries the most flexible model available and tunes it until the score stops improving.

Retrains whenever a drift alert fires, which can mean a week of work every quarter.

This analysis

Shows the simpler model won (AUC 0.598 against 0.545) and that no model could pass about 0.72 with the data collected, so the next gain is in collecting different data, not in tuning.

Retrains only when two of three signals agree, which here avoided a retrain the model did not need.

When the simple approach is enough: in this data the simple model was enough, and knowing that early is part of the result. With richer data a flexible model might win, and the same comparison would show it.

Which model, and how much better it could get

Each student becomes one row per month enrolled, with the outcome 1 in the month they left, so any classifier estimates the monthly chance of leaving. The 1,400 students become 11,675 rows. The split into training and test sets is by student (1,050 and 350), because splitting rows at random puts the same student on both sides and makes the test score look better than it is.

Logistic regression beat gradient boosting on both AUC and calibration. Because the published data is artificial, each student’s true risk is known, so the ceiling can be computed rather than guessed. A model that knew the true effect of every recorded feature would score 0.591, which the logistic model already passes (it also sees how long each student has stayed, which says something about them). A model that knew each student’s true risk would score 0.721. That gap is 56% of all the signal above chance, and it comes from differences between students that the center never recorded.

Most of the missing signal was never recorded, so no model could reach it

Held-out AUC for the two fitted models and two oracles that know things no model can see. 0.5 is a coin flip.

Table view

So the recommendation was to stop tuning and start collecting something closer to what was missing: attendance over time rather than an eight-week average, whether a parent replies to progress emails, and grade changes in the student’s own class. Any one of these could plausibly carry more than the whole existing feature set.

What the call list can and cannot do

The deliverable is a ranked list of the 570 current students, each with a value at risk: the chance of leaving within three months, times expected remaining months, times tuition and margin. The total is about $216,000 of margin over three months.

The 25 highest-value students hold only 5% of the value at risk, so there is no short list

Share of total value at risk covered by contacting the top students on the list, against contacting the same number at random. Move the slider or hover.

That changes the shape of the intervention. A hand-picked rescue list would have been more satisfying to deliver and would have missed most of the money. Whatever the center does has to be cheap enough to apply to most of the roster. (Which students to contact is a different question from who is most likely to leave, and it has its own case study.)

From an analysis to a tool

A model that only runs in a notebook stops being used when its author leaves. So the scoring step is a command-line tool that someone else can run on new data:

python src/score.py train   # fit both models, keep the one that won on held-out students
python src/score.py score   # check the input, then write the ranked call list
python src/score.py check   # compare new data with training data, exit code 2 if retraining is due

The score step checks its input before predicting: a missing column, a value out of range, or a channel the model has never seen stops the run. The failure this prevents is a renamed column producing confident, wrong numbers for months with nothing looking wrong. The saved model carries a fingerprint of the rows it was trained on, so any call list can be traced back to its training data. The check step exits with code 2 when it says to retrain, so it can block a scheduled job instead of printing to a log nobody reads. The same model is also served over HTTP (FastAPI, packaged in Docker), with the same input checks, so a CRM or a scheduled job can request scores directly. The repository has 45 tests that check results against known answers, and GitHub Actions runs them, builds the Docker image, and checks that the service answers on every push.

When the drift alarm is wrong

The model was trained when most new students came from paid search. The center’s marketing work then moved new enrollment toward organic search and referrals, from 55% paid to 18%. Improving the business changed the data the model sees, which is exactly what a drift alarm measures.

By the third quarter the PSI on the channel feature reached 0.60, more than twice the usual threshold for retraining. But accuracy did not move: AUC changed by 0.012 and calibration error stayed under 8%. The mix of students changed, and the relationship between each student’s features and leaving did not, so the model kept working.

Table view

A team that retrains on every PSI breach spends a week a quarter on it and teaches everyone to ignore the alert. So the rule here needs two of three signals to agree: PSI at or above 0.25, calibration error at or above 30%, or AUC down 0.03 or more. The case that should always raise an alarm is the reverse of this one, calibration getting worse while PSI stays flat, because it means the relationship itself has changed.

What holds generally, and what is specific to this data

Several of these lessons hold for any project of this kind. Data with many rows per customer has to be split by customer. A more flexible model cannot recover signal that was never recorded. A change in the mix of inputs does not hurt a model whose relationship between inputs and outcome still holds, so drift scores alone are a poor reason to retrain.

The sizes are specific to this data: the two AUCs, the 56% share, the 5% held by the top 25, and the PSI of 0.60.

Where else this applies

The same build and checks apply to churn models for subscriptions, gyms, and software, to lapse and default models in insurance and lending, and to employee attrition. The drift lesson applies to any deployed model after a business change, such as a new marketing channel, product line, or region.

Details for technical readers

Model. Discrete-time hazard on the person-month frame, so the classifier estimates

h(t | x) = Pr(leaves in month t | enrolled at the start of t, x),   Ŝ(t | x) = ∏k ≤ t (1 − ĥ(k | x))

Censoring needs no special handling: a student still enrolled at the cut stops contributing rows.

Oracles. The data was generated with hazard zi λ exp(βTxi), where zi is a Gamma frailty. The covariate oracle scores held-out rows with λ exp(βTx), and the full oracle with zi λ exp(βTx). The unobservable share is (0.721 − 0.598) / (0.721 − 0.5) = 56%.

Permutation importance (drop in held-out AUC):

Value at risk. Pr(leaves within 3 months) × E[remaining months] × tuition × margin. In this data, sorting on probability alone gives almost the same order (4.7% of value in the top 25 against 4.9%), because expected remaining months vary little among the highest-risk students. Where remaining value varies more, the two orders separate.

Drift. PSI = Σ (ci − ri) ln(ci / ri), a symmetrized Kullback-Leibler divergence between binned distributions. Bin edges come from the reference window and are then frozen, since recomputing them on current data hides the shift being measured. The slider computes PSI for the binary paid feature directly from the shares, so it differs slightly from the measured values in the table (0.635 against 0.599 at 18%).
